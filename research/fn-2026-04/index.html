FIELD NOTES · FN-2026-04 · 25 November 2026

No patch, and a setting Danfoss has decided to stop offering

CISA published an advisory on 24 November for refrigeration controllers used across food retail. The flaw needs no password, there is no fix yet, and the fix when it arrives will take away a choice customers have today. That last part is the interesting one, because it says the option itself was the defect.

Key points

  • CISA advisory ICSA-26-328-03 of 24 November 2026 covers Danfoss AK-SM 8xxA controllers at software version 5.4.0 and earlier. CVE-2026-129713 scores 9.8 on CVSS v3.1 and 9.3 on CVSS v4.0.
  • The flaw is a stack-based buffer overflow in an unauthenticated CGI handler, reached by a crafted HTTP or HTTPS POST. The advisory states that authentication is not required to exploit it.
  • There is no fix. Danfoss says it will come in an upcoming 5.5.x release, with no date, and that it will also remove the ability for users to disable Strict Mode.
  • The protection already exists on the installed base and can be switched off today, which makes the question for this week whether Strict Mode is on rather than whether the controller is patched.

What the advisory says

  • The equipment. Danfoss AK-SM 8xxA series controllers at software version 5.4.0 and earlier. CISA records the sector as Commercial Facilities, deployment as worldwide, and the manufacturer as headquartered in Denmark.
  • The flaw. CVE-2026-129713, a stack-based buffer overflow (CWE-121) in an unauthenticated CGI handler. A crafted HTTP or HTTPS POST request reaches it. CVSS v3.1 scores it 9.8 with the vector AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H; CVSS v4.0 scores it 9.3.
  • No credential is needed. The advisory states plainly that authentication is not required to exploit it.
  • What it actually does. Memory corruption and a restart of the web server, and, in the advisory's own careful phrasing, hypothetically potential arbitrary code execution with web server privileges. The first two are asserted; the third is not.
  • No fix today. Danfoss says the vulnerability will be addressed in an upcoming AK-SM 800A software release, version 5.5.x. No date is given.
  • The researcher. Carlo Meijer of Midnight Blue reported it to CISA.
  • Nothing is known to be exploited. CISA states that no known public exploitation specifically targeting this vulnerability has been reported to it.

The interim advice names the setting

Until the release exists, Danfoss asks operators to keep the controllers off the public internet and off public IP addresses, to reach them only through a VPN or equivalent protected architecture, to use strong unique passwords, and to configure all affected devices to operate in Strict Mode.

Then comes the sentence worth reading twice. Danfoss says it will remove the ability for users to disable Strict Mode in future releases.

Put the two together and the shape of the problem is clear without any inside knowledge. The protection exists already. It is available on the installed base, today, at no cost and with no update. It can be switched off, and the vendor has concluded that being able to switch it off was a mistake worth correcting in software.

So the question an operator should be asking this week is not whether the controller is patched, because it cannot be. It is whether Strict Mode is on, and if it is not, who turned it off and what stopped working when it was on.

What the advisory does not say

It does not connect this vulnerability to the attacks on European food retailers in October and November. Neither will we. Danfoss did say its software was involved in the November cases and that the customers affected had not applied an update, and this advisory arrived three weeks later for the same product family, and both of those things can be true without the one causing the other. CISA says no exploitation of this CVE has been reported to it, and that sentence is the most load-bearing one in the document.

We also could not read the Danfoss advisory itself. The page returns 403 to us, so everything attributed to Danfoss above is as CISA reproduces it. We would rather say that than present a second-hand reading as a first-hand one.

Our analysis

An unauthenticated CGI handler on a refrigeration supervisor is the same finding as the one in our November note, arriving from a different manufacturer. The supervisor exists to bridge a web interface for people and a field bus down to the case controllers. Anything that reaches the web side without a credential has already crossed the only boundary that mattered, and the severity number attached to it is a detail by comparison.

The restart deserves more attention than it usually gets. A web server that can be made to restart from an unauthenticated request is a denial of the management path, and on this class of device the management path is also the monitoring path. An operator who loses it does not lose cooling, but does lose the ability to see that cooling is in trouble. That is worth something to an attacker even if the code execution never materialises.

The optional control is the part we would write up for a client. Security settings that ship switchable tend to get switched, and not by the person who owns the risk. On this class of equipment the switching is usually done by a refrigeration contractor during commissioning, because something in the remote access path did not work with the protection on and the job had to be finished that afternoon. Nobody records it. The setting then survives every subsequent service visit, because nobody knows it was ever changed. Danfoss removing the option is the right correction, and it also tells you what has been happening in the field.

Which leaves a concrete piece of work that does not need a patch and does not need us. Find the controllers. Establish whether each one is reachable from outside, and from where. Read the Strict Mode state on each, not the intended state but the actual one. Write down what you find, including who maintains the device and under which contract, because that is the field that will be blank and it is the one that explains the rest.

Questions

What is CVE-2026-129713?

A stack-based buffer overflow, CWE-121, in an unauthenticated CGI handler of the Danfoss AK-SM 8xxA series refrigeration controller at software version 5.4.0 and earlier. A crafted HTTP or HTTPS POST request causes memory corruption and a restart of the web server, and the advisory describes arbitrary code execution with web server privileges as hypothetically potential rather than as demonstrated.

Is there a patch?

Not yet. Danfoss says the vulnerability will be addressed in an upcoming AK-SM 800A software release, version 5.5.x, and gives no date. Until then the response is network position and configuration: keep the controllers off the public internet and off public IP addresses, reach them only through a VPN or equivalent protected architecture, use strong unique passwords, and run every affected device in Strict Mode.

What is Strict Mode and why does it matter here?

It is a hardening mode already present on the installed base, available today without any update. Danfoss asks operators to enable it as the interim mitigation, and says it will remove the ability for users to disable it in future releases. A protection that ships switchable tends to get switched, usually during commissioning and usually by a service contractor, and nobody records it. Reading the actual state on each device is work that needs no patch.

Was this vulnerability used in the supermarket refrigeration attacks?

There is no basis for saying so. CISA states that no known public exploitation specifically targeting this vulnerability has been reported to it, and the advisory does not connect it to the October or November incidents. Danfoss did say its software was involved in the November cases and that the customers affected had not applied an update, but that is a separate statement about a separate matter.

Does the absence of a patch suspend the NIS2 and KSC obligations?

No. The duty is to manage risk rather than only to apply updates. Where no fix exists, documented compensating controls are what an operator presents: network position, remote access through a VPN, the hardening mode enabled, and a replacement date. They count when they have been written down and assessed, not merely performed.
